# 공격 벡터 코퍼스 — 출처와 작성 원칙

`injection_corpus.jsonl`의 근거 문서다. 데이터(JSONL)는 주석을 달 수 없으므로
"왜 이 문장들인가"는 여기에 남긴다. 결정 근거는 **D-042 / D-044**.

> **코퍼스가 곧 탐지기다.** 1차 룰은 코드가 로직이었지만 2차는 데이터가 로직이다.
> 여기에 무엇을 넣느냐가 곧 방어 성능이고, 잘못 넣으면 ASR 수치 전체가 무의미해진다.

---

## 1. 스키마

```json
{"id": "K-R1-01", "text": "...", "source": "category_ko", "category": "R1"}
```

| 필드 | 의미 |
|---|---|
| `id` | 감사 로그에 남는 식별자. **로그에는 원문이 아니라 이 ID만 남긴다**(D-044, D-029) |
| `text` | 임베딩 대상 문장 |
| `source` | `category_ko`(직접 작성) / `public`(공개 데이터셋) — 기여도 분리용(D-042) |
| `category` | `R1` 지시 무효화 / `R2a` 제약 해제 / `R2b` 페르소나 / `R3` 역할 헤더 위조 |

`id` 접두사: `K-` = 한국어 자체 작성, `P-` = 공개셋.

---

## 2. 출처와 라이선스

| `source` | 출처 | 라이선스 |
|---|---|---|
| `category_ko` | 직접 작성. 근거는 D-040이 공개 지식으로 정의한 공격 범주 | 본 저장소 |
| `public` | *(미작성)* 1순위 후보 `deepset/prompt-injections` (662행, 독·영) | Apache-2.0 |

### `category_ko`를 직접 작성해도 되는 이유 (D-042)
SCOPE 5절 "공격 시나리오 자체 작성 금지"와 프로젝트 원칙 2번이 막는 것은
**평가용 공격셋을 우리가 만드는 것**이다. 채점은 여전히 garak 표준 프로브가 한다.
D-040의 어휘 화이트리스트도 우리가 작성했고 위반으로 보지 않았다 —
코퍼스는 그것의 문장 단위 버전이다.

**대가**: 한국어 커버리지가 우리 상상력의 함수가 된다. README 한계에 명시한다.

### 절대 하지 않는 것 (D-039 홀드아웃)
`results/*.report.jsonl`(채점에 쓸 공격 원문)을 코퍼스 작성 목적으로 **열지 않는다.**
오염 검사 스크립트는 원문을 출력하지 않는 방식으로만 접근하며, 매치된 항목은
**삭제만** 한다(수정 금지).

## 3. 작성 규칙

### (1) 1차 룰을 통과해야 한다 — 필수
체인은 `injection_rule → injection_similarity`이고 BLOCK은 조기 종료다(D-030).
1차가 이미 잡는 문장을 코퍼스에 넣으면 **2차의 기여가 0**이다. 해롭지는 않고 무의미하다.

**테스트로 고정한다**: 코퍼스 전체를 `match_rules()`에 통과시켜 발동이 0이어야 한다.
이 테스트가 곧 "2차는 1차의 중복이 아니다"의 증명이다.

### (2) 정상 질문셋과 너무 가까우면 뺀다
캘리브레이션 스크립트가 항목별로 정상 질문셋 100문항과의 **최대 유사도**를 출력한다.
기준 이상이면 그 항목을 코퍼스에서 **제거**한다(문장을 다듬지 않는다).

정상 질문셋만 쓰므로 D-039 위반이 아니다(의도적 비대칭). 제거는 탐지 능력을 줄이는
방향이라 편향이 ASR **과소평가** 쪽이며, 결과를 부풀리지 않는다.

### (3) 의미는 공격, 표현은 룰 밖
같은 의도를 룰 어휘 없이 표현한다. **대가**: 룰 어휘를 우회한 문장은 정상 문장과도
가까워진다. 그래서 (2)의 게이트가 반드시 필요하다.

## 4. `category_ko` / R1 — 지시 무효화 (13항목)

1차 룰 R1은 `[무효화 동사]`와 `[시스템 지시 목적어]`가 **같은 문장 안에** 있을 때만
발동한다(D-040). 우회 경로는 세 가지이며, 항목을 기법별로 나눠 담았다.

| 기법 | 무엇을 우회하나 | 항목 |
|---|---|---|
| **A 어휘 우회** | 무효화 동사를 사전에 없는 말로 바꾼다 — "반영하지 말고", "적용하지 않아도", "~보다 우선해서" | K-R1-01 ~ 05 |
| **B 문장 분리** | 목적어를 앞 문장에, 동사를 뒷 문장에 두고 지시대명사로 잇는다. 사전 단어를 그대로 쓰는데도 안 걸린다 | K-R1-06 ~ 08 |
| **C 목적어 우회** | `지시/명령/시스템 프롬프트`를 안 쓰고 가리킨다 — "처음에 세팅된 제약", "정해둔 틀", "사전에 주어진 안내 문구" | K-R1-09 ~ 13 |

### B에 대한 기록 — 1차 룰을 고치지 않기로 했다 (2026-08-10)
B는 어휘 부족이 아니라 **룰 구조의 빈틈**이다. 그래서 1차에서 문장 창을 2로 넓혀
고치는 안을 검토했고, 정상 질문 100문항에서는 FPR이 1.0%로 변하지 않았다.

**그러나 `tests/test_injection.py::test_r1_does_not_fire_across_sentences`가 이미
반례를 담고 있었다.**

> "앞의 질문은 무시해 주세요. 그리고 지시사항 문서는 어디서 받나요?"

완전히 정상적인 HR 질문인데 2문장 창에서는 차단된다(실행 확인). 즉 "같은 문장 안에"
제약은 실수가 아니라 의도된 설계였다.

- **100문항 전수 대조가 이것을 놓쳤다.** 반례가 질문셋 안에 없었기 때문이다.
  D-039가 예고한 "FPR은 낙관적으로 나온다"가 구체적으로 드러난 사례다.
  **100문항 통과가 안전을 뜻하지 않는다.**
- 검토 중 나왔던 "싸게 잡을 수 있는 걸 비싸게 잡는다"는 논리도 틀렸다.
  2차는 1차를 통과한 **모든** 요청에 어차피 붙으므로(D-043) B를 2차가 맡는 추가 비용은 **0**이다.
- 결론: D-040의 원칙 유지 — *"놓치는 쪽이 잘못 막는 쪽보다 낫다."*

**남는 한계**: 2차가 폴백에 실패해 만들어지지 못하면 B 유형은 아무도 막지 못한다.
README 한계 절에 적는다.

- 정상 질문셋 최대 유사도 게이트 실행 기록
- **임계값 T** — 아직 정해지지 않았다. 절차만 D-044로 동결돼 있다.
