# 보안 백서 — LLM 보안 게이트웨이

보안 담당자가 읽는 문서다. 이 제품이 **무엇을 어디서 어떻게 바꾸고, 무엇을 저장하지 않으며, 무엇을 막지 못하는지**를 한 흐름으로 적는다. 숫자는 저장소 `DECISIONS.md`의 측정값만 인용하고 결정 번호를 병기한다. 설정 항목은 [설정](configuration.md), 운영 절차는 [운영](operations.md), API별 범위는 [API 호환 범위](api-compat.md), 법적 위치는 [법적 위치 메모](legal-position.md). (D-129, 2026-11-04 작성 · 2026-11-10 리뷰 반영)

## 1. 무엇을 하고, 무엇이 아닌가

- **하는 일**: 고객이 자체 호스팅하는 역방향 프록시다. 클라이언트(앱·SDK)가 OpenAI·Anthropic 호환 API 요청을 게이트웨이로 보내면, 게이트웨이가 요청 본문의 한국 개인정보 꼴을 **같은 모양의 가짜 값**으로 바꿔 상류(LLM 공급자)에 보내고, 응답(스트리밍 포함)의 가짜 값을 **원래 값으로 되돌려** 클라이언트에 준다. API 요청(세 API와 모델 목록, 거절한 요청 포함)은 모두 **감사 줄** 한 줄(원문 없음)로 남는다 — 게이트웨이 자체 경로(`/__gateway/*`)는 남기지 않는다.
- **아닌 것**: SaaS가 아니다(우리는 고객 데이터를 받지 않는다). 익명화 도구가 아니다(식별자 꼴만 바꾼다). 모델 출력의 유해성·정확성을 보장하지 않는다. 응답 방향의 개인정보는 세기만 하고 가리지 않는다. 인젝션(프롬프트 주입)은 기본적으로 **관측**하고, 차단은 운영자가 켠다.

## 2. 데이터 흐름

```
클라이언트 ──TLS(배포 몫)──▶ 게이트웨이 ──HTTPS──▶ LLM 공급자
                 │ ① 인증(클라이언트 키 → 정책)
                 │ ② 경로·헤더 허용 목록, 본문 상한
                 │ ③ 검사 체인: 인젝션 룰 → PII 가림(정규식 12종 + 켜면 NER) → 가드레일 웹훅(켜면)
                 │ ④ 상류 호출(공급자 키는 게이트웨이가 단다)
                 │ ⑤ 응답·스트림에서 가짜 값 → 원문 복원, 응답 방향 개인정보 세기
                 └ ⑥ 감사 줄(원문 없음) · 지표 · 대시보드
```

1. **인증·정책**: 클라이언트 키(`GATEWAY_CLIENT_KEYS` 또는 설정 파일 `[[clients]]`)는 SHA-256으로만 들고, 키마다 정책(가림 종류·모드·인젝션·허용 모델·가드레일)을 고른다(D-119). 키가 없으면 기동하지 않는다. 인증을 끄는 모드는 로컬 실험용이며 공급자 키와 함께 쓰면 기동 실패다(D-109).
2. **경계**: 경로는 `POST /v1/chat/completions`·`/v1/responses`·`/v1/messages`, `GET /v1/models`만 — 그 밖은 404. 요청·응답 헤더는 허용 목록만 통과하고, 클라이언트의 인증 헤더는 상류로 가지 않는다. 본문 상한(기본 1MiB)·탐지 상한(5,000)·동시 연결·레이트리밋이 있다(D-109·D-110). `X-Forwarded-For`는 믿지 않는다.
3. **검사 체인**(정책마다, 순서 고정 — D-127): 인젝션 룰(두 개, 기본 관측) → PII 가림 → 가드레일 웹훅(기본 꺼짐, 체인 **마지막**이라 웹훅은 공급자가 받을 것과 같은 텍스트 — 정책이 가리는 종류는 가짜 값 — 를 본다). 어느 검사기가 거절하면(413·503 등) 상류를 부르지 않는다.
4. **가림**: 역할 `user`·`assistant`·`tool`·`system`의 텍스트(도구 호출 인자, Anthropic `document`·`search_result`·`tool_result` 안의 문서 포함 — D-127)에서 찾은 값을 가짜 값으로 바꾼다. 사고 과정(thinking·reasoning)은 손대지 않아 공급자의 서명 검증·프롬프트 캐시가 유지된다(D-111·D-114에서 실 공급자로 확인).
5. **복원**: 응답 본문의 문자열 필드(스트리밍 조각 경계 포함)에서 가짜 값을 원문으로 되돌린다(D-113). 되돌리지 못한 가짜 값은 `pii_suspect`로 센다. 응답에 새로 나온 개인정보 꼴은 `pii_new`로 센다(가리지 않는다).
6. **기록**: 감사 줄 한 줄(아래 3절), Prometheus 지표(`/__gateway/metrics`, 관리 키), 읽기 전용 대시보드(`/__gateway/dashboard`, 관리 키 — 원문·가짜 값·IP 없음, D-124).

## 3. 저장하지 않는 것

- **요청·응답 본문**: 어디에도 쓰지 않는다. 감사 줄에는 크기(`req_bytes`·`res_bytes`)와 요청 본문의 SHA-256 앞 12자(`req_sha256_12`)만 있다. 접근 로그(uvicorn access log)는 꺼져 있다. URL 쿼리는 **키 이름**만 남긴다(`query_keys`).
- **원문↔가짜 값 대응표(볼트)**: 요청 단위 **메모리**. 응답이 끝나면 바로 버리고, 남은 세션은 상류 응답 기한 + 60초 뒤에 지운다(안전망). 세션 상한(정책·워커마다 2,000)에 닿으면 **진행 중인 세션을 밀어내지 않고 새 요청을 503 `gateway_busy`로 거절한다**(D-110). 재시작하면 사라진다. 디스크·외부 저장소·다른 파드와 공유하지 않는다 — 그래서 서버 저장 대화(`previous_response_id`)의 복원은 지원하지 않는다(결정 표 4번).
- **감사 줄에 있는 것**(D-107~D-127): 시각, 요청 ID, 메서드·경로, 상태·오류 코드, 지연(`total_ms`·`upstream_ms`·`gateway_ms`), 크기·지문, 클라이언트 키 **이름**, IP, API·모델·토큰 사용량(`usage`), 정책·설정 버전, 상류 요청 ID, 검사기별 결과(종류별 **개수**, 탐지 앞 100건의 **위치·길이·확신도**, 가림/감사만, 인젝션 룰이 붙잡은 **어휘**(우리 사전의 단어), `would_block`, 가드레일 판정·점수, 사이드카 오류), 발급·복원·의심·새 개인정보 **개수**, 쿼리의 키 이름과 크기. **값은 없다**(위치와 길이는 있다).
- **검사기로 가는 텍스트**: 이름·주소를 켠 정책은 **가리기 전 텍스트**를 탐지 사이드카로 보낸다. 가드레일을 켠 정책은 공급자가 받을 텍스트(정책이 가리는 종류만 가짜 값이고 **그 밖은 원문**)를 웹훅으로 보낸다 — 외부 가드레일 서비스를 붙이면 그곳이 또 하나의 처리자가 된다. 둘 다 인증 없는 평문 HTTP라 같은 파드·내부망에 둔다(5절 신뢰 경계).
  사이드카는 텍스트를 저장하지 않는다. 다만 게이트웨이와 사이드카는 같은 글을 다시 재지 않으려고 **텍스트의 SHA-256별 결과**(구간·점수 — 글 자체는 아니다)를 프로세스 메모리에 캐시하고, 이것은 요청이 끝난 뒤에도 남는다(재시작하면 사라진다).
- **기동·오류 로그(stderr)**: 처리 중 예외의 트레이스백이 남는다. 감사 로그와 같은 등급으로 접근을 통제한다.
- **키**: 공급자 키·대체값 키·관리 키는 환경변수(쿠버네티스 Secret)로만 들고 로그·오류 응답·지표에 쓰지 않는다. 설정 파일에는 키가 아니라 **환경변수 이름**(`key_env`)만 적는다(D-119).

## 4. 대체값과 키

- **결정적 대체값**(D-111): 가짜 값 = HMAC(대체값 키, 종류 + 정규화한 원문)으로 정해지는 난수 열에서 **같은 모양**으로 만들고, 검증 숫자가 있는 종류는 맞춘다(카드 Luhn, 사업자·법인 검증 숫자 — 주민·외국인등록번호는 날짜·성별 자리만 맞추고 검증 숫자는 맞추지 않는다). 그래서 같은 원문은 같은 턴·같은 대화에서 늘 같은 가짜 값이 되어 공급자의 프롬프트 캐시와 다중 턴 대화가 깨지지 않는다(D-114). 키가 같으면 요청·사용자가 달라도 같은 원문은 같은 가짜 값이다(9절 '요청 간 연결').
- **가짜 값은 실제 값과 겹칠 수 있다**(D-113): 예약 대역을 쓰는 것은 **이메일뿐**이다(RFC 2606의 `example.com`·`.net`·`.org` — 실제 주소가 되지 않는다). 전화는 국내 접두사를 그대로 두고 나머지 숫자만 바꾸므로 **실제로 쓰이는 번호일 수 있다** — 국내에는 공식 가상 번호 대역이 없다. 카드·주민번호 꼴 가짜 값도 실제로 발급된 값과 겹칠 수 있다. 복원에 실패하면 사용자가 제3자의 번호를 받을 수 있으므로 `pii_suspect`를 지켜본다(9절).
- **키 취급**(결정 표 8번): `GATEWAY_SURROGATE_KEY`(32자 이상). 원문을 되짚을 수 있는 키이므로 **공급자 키와 같은 등급**으로 보관하고, 법률 검토 전까지 개인정보 보호법 제28조의4의 **추가정보**로 취급한다(법적 위치 메모 2-4). 회전은 수동이며 절차는 [운영 — 키 회전](operations.md#키-회전). 복원은 키가 아니라 요청 단위 대응표로 하므로 **회전이 복원을 깨지 않는다** — 바뀌는 것은 가짜 값이다: 진행 중인 대화의 다음 턴에서 이력의 가짜 값이 달라져 프롬프트 캐시 미스와 thinking 서명 400이 날 수 있다(D-111·D-114).
- **공급자가 보는 것**: 가짜 값은 원문과 같은 꼴이므로 공급자 쪽 로그·학습·보존에는 **가짜 값**이 남는다. 공급자가 받은 텍스트의 나머지(맥락·형식 없는 개인정보)는 원문이다 — 9절 '막지 못하는 것'.

## 5. 위협 모델

| 자산 | 위협 | 대응 | 남는 위험 |
|---|---|---|---|
| 요청 속 원문 개인정보 | 공급자 보존·학습, 공급자 측 유출, 전송 구간 도청 | 식별자 꼴을 가짜 값으로(2절), 공급자 연결은 상류 주소를 `https://`로 두면 HTTPS(게이트웨이가 강제하지는 않는다), 클라이언트 구간 TLS는 배포 몫 | 형식 없는 개인정보·감사만 종류·지원하지 않는 꼴은 원문으로 간다(9절) |

| 간접 프롬프트 주입(문서·도구 결과 속 지시) | 모델이 지시를 따라 데이터 유출·행동 | 인젝션 룰(관측·차단), 가드레일 웹훅(사이드카 분류기 또는 외부 가드레일 — 체인 마지막이라 정책이 가리는 종류는 가짜 값으로 간다. 그 밖은 원문 그대로다) | 분류기는 한 겹이다 — 숫자는 6절, 적응형 공격자는 피해 갈 수 있다 |
| 컨테이너·배포 | 권한 상승, 변조된 베이스 | 비root(uid 10001), 다이제스트로 고정한 베이스 이미지, 헬스체크, k8s 견본은 읽기 전용 설정·Secret·PDB(D-109·D-121). 릴리스 이미지(0.2.0부터)는 취약점 스캔 게이트·cosign keyless 서명·SBOM 증명(D-130) | 스캔 게이트는 고칠 수 있는 HIGH·CRITICAL만 본다. 서명 검증은 받는 쪽이 해야 한다 |

**신뢰 경계**: 클라이언트↔게이트웨이는 고객 내부망(또는 고객이 두는 TLS 종단), 게이트웨이↔공급자는 공용 인터넷(HTTPS). 탐지 사이드카·가드레일 웹훅은 **같은 파드/내부망**에 두고 인증 없이 부른다 — 외부 가드레일 서비스는 같은 클러스터의 어댑터가 받는다(D-127).
**범위 밖**: 호스트·오케스트레이터 침해, 공급자 측 데이터 처리 정책, 모델 출력의 유해성, 응답 방향 마스킹(조건부), 영속 대응표(조건부).

## 6. 탐지 범위와 숫자

- **정규식 12종**(기본 가림 8: 주민등록번호 `rrn`·외국인등록번호 `frn`·여권 `passport`·운전면허 `driver`·카드 `card`·전화 `phone`·이메일 `email`·비밀 키 `secret`; 기본 감사만 4: 사업자 `brn`·법인 `crn`·계좌 `account`·IPv4 `ipv4`). 정규화(전각·제로폭·대시 변형)를 거쳐 찾고, 검증식이 없는 약한 꼴은 감사만으로 내린다(D-116·D-117). 합성 코퍼스(양성 1,200·음성 1,200)에서 종류마다 오탐 1% 이하가 CI 게이트다(D-115·D-117).
- **이름·주소·직장**(`person`·`address`·`org`, 정책에서 켬 — D-126): 탐지 사이드카의 한국어 NER(`1T/veil-pii-ko-lite` INT8) — 합성 문장 F1 0.963·실제 대화(KDPII) 0.895, 지연은 x86 4 vCPU에서 510토큰 p95 약 200ms(D-125). 직장은 감사만.
- **인젝션 룰**(기본 관측): 공개 평가셋 v1(6,871행, 봉인 홀드아웃 1,379 — D-123) dev에서 재현율 8.7%(한국어 5.9%)·오탐 2.7%. **차단 도구가 아니다.**
- **인젝션 분류기(가드레일 웹훅, 기본 꺼짐)**: 한국어로 이어 학습한 `injection-ko-small-int8`(D-128) — 운영 문턱(학습 쪽을 뺀 개발셋의 정상 오탐 1%로 고른 값)에서 봉인 홀드아웃 한국어 공격 97.5%·영어 93.8%, **그 문턱의 홀드아웃 정상 오탐은 2.3%**(한국어 7/470 = 1.5%, 영어 6/114 = 5.3%). 홀드아웃 정상 오탐을 1%로 맞추면 한국어 90.6%·영어 84.1%다. 학습 쪽을 뺀 개발셋은 한국어 85.9%(더 어렵다 — 두 숫자를 함께 본다). 판정 조작 문구 양성대조는 최대 0.7%(기준 5% — 같은 수법을 다른 문구로 학습한 모델이라 처음 보는 수법의 값은 아니다). 관측 기간 뒤 차단에 쓸 수 있다. **이 모델은 아직 배포 이미지에 없다**(모델 공개 전) — 지금 이미지에 든 공개 모델(Horizon guard base)은 홀드아웃 한국어 61.7%·양성대조 8.9%로 관측 전용이다(D-127).
- **실 공급자 확인**: Claude 2턴에서 사고 과정 서명·프롬프트 캐시가 유지됨(D-114). 공식 SDK 호환은 스텁 상류로 점검했다 — OpenAI 8/8·Anthropic 6/6(D-121).

## 7. 배포 보안

이미지는 비root(uid 10001)로 돌고 베이스 이미지는 다이제스트로 고정한다. 접근 로그 끔, 종료 유예 25초(처리 중 요청 완료), 동시 연결 상한. 쿠버네티스 견본(`deploy/k8s/`)은 설정(ConfigMap)·키(Secret)를 분리하고 내용 해시로 롤링 재시작, PodDisruptionBudget, 읽기 전용 설정 마운트를 쓴다(D-121). 사이드카(탐지·분류기)는 같은 파드의 둘째 컨테이너이고 Service로 내지 않으며 게이트웨이는 `127.0.0.1`로 부른다. 다만 사이드카 포트(8081)는 **인증이 없고 파드 IP로 클러스터 안에서 닿는다** — 견본의 NetworkPolicy(`deploy/k8s/networkpolicy.yaml`, 8080만 받는다)를 함께 적용한다(NetworkPolicy를 집행하는 CNI가 있어야 한다). 릴리스 이미지(0.2.0부터)는 올리기 전에 취약점을 스캔하고(고칠 수 있는 HIGH·CRITICAL이 있으면 릴리스가 실패한다), 키 없이(cosign keyless — GitHub OIDC·투명 로그) 서명하며 SBOM(SPDX)을 증명으로 붙인다. 받는 쪽은 저장소·워크플로·태그 신원으로 검증하고 다이제스트로 고정한다(D-130, 운영 문서 '업그레이드'). 비밀 검사(gitleaks)와 의존성 알림(dependabot)이 CI에 있다.

## 8. 감사와 관측

- 감사 줄(JSONL, 파일 또는 stdout, 회전)은 요청마다 **같은 모양**이다 — 예외로 끝난 요청도. 집계는 `pii_issued`·`pii_restored`·`pii_suspect`·`pii_new`, 검사기별 `unmasked`(감사만 종류 개수), `would_block`, 가드레일 `guard_verdict`·`guard_score`를 본다(D-113·D-120·D-127).
- 지표(Prometheus): 결과별(`gateway_outcomes_total{outcome,reason}`), 가림 종류별, 복원 의심, 가드레일 오류·판정, 사이드카 오류, 볼트 세션 수. 장애 신호 목록은 [운영 — 장애 신호](operations.md#장애-신호).
- 대시보드(관리 키): 최근 요청 200건의 결과·사유·가린 종류 수 — 원문·가짜 값·위치·IP 없음(D-124).

## 9. 막지 못하는 것·한계

- 지원하지 않는 꼴과 **형식 없는 개인정보**(기본 꺼짐인 이름·주소를 켜지 않았을 때, 병력·관계 서술 등)는 원문으로 간다. 감사만 종류(계좌·사업자·법인·IPv4·직장)도 원문으로 간다.
- **응답 방향**은 세기만 한다. 모델이 스스로 만든 개인정보는 사용자에게 간다.
- **복원 실패**는 조용하다 — 모델이 가짜 값을 알아볼 수 없게 고쳐 쓰면 사용자가 가짜 값을 받는다(`pii_suspect`로 본다). **가짜 휴대전화 번호는 실제로 쓰이는 번호일 수 있다** — 사용자가 제3자의 번호를 받을 수 있다(가짜 이메일만 예약 도메인이다, 4절).
- **보지 않는 자리**: 비텍스트(이미지·PDF 원본·오디오·파일 ID로 가리킨 내용), 텍스트가 아닌 블록, 도구 정의, Responses의 사용자 정의 도구 — 그 안의 개인정보는 그대로 나간다. 가리는 자리는 [API 호환 범위](api-compat.md)에 API별로 있다.
- **요청 간 연결**: 같은 대체값 키 아래 같은 원문은 늘 같은 가짜 값이라, 공급자 쪽에서 같은 값을 담은 요청끼리 이어 볼 수 있다(키를 바꾸면 끊긴다).
- **가짜 값에 원문 일부가 남는다**: 모양을 지키느라 전화의 접두사, 카드의 첫·끝 자리, 운전면허 지역, 사업자 앞 5자리·법인 앞 7자리, 계좌 앞 3자리, IP 첫 묶음, 이메일의 길이·구두점은 그대로다.
- 인젝션 룰은 어휘 밖을 보지 못하고, 분류기는 한 겹이다(6절). 이전 턴은 다시 보지 않는다.
- 사고 과정에 보이는 가짜 값은 복원하지 않는다(서명 보존).
- 자체 호스팅이라 **고객의 배포 보안(TLS·네트워크·로그 접근 통제·키 보관)**이 전제다.
